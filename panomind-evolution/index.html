Panomind: from frame geometry to reliable aerial-panorama batch production

Panomind is built for multi-frame aerial panoramas where ordinary automatic stitching is not enough: strong perspective, elevation changes, repeated structures, reflections, water, moving traffic, and large batches of similar projects. It makes the PTGui workflow observable, controllable, and repeatable.

  • LVL toolsgeometry, control points, verticals, and analysis of scenes with walls and structures
  • Panomind Overlaylive connection audit directly in PTGui Panorama Editor
  • Panomind Studiomodel-guided CP selection, presets, and dependable headless batch work

Development chronology

How the project evolved: three stages of development and experimentation

This is not an architecture diagram, but a short development history. Each stage emerged from the limits of the previous one: first the engineering utilities, then visual control inside PTGui, and finally Studio with reproducible processing for project series.

01 / DEVELOPMENT STAGE: LVL

Tools for geometry and vertical structures

The initial challenge was engineering: read PTGui .pts projects, calculate projections, and automate operations that do not scale manually when imaging buildings, structures, and other scenes with strong verticals.

  • the exact chain “frame pixel → world ray → panorama”;
  • regular CP t=0 and automatic vertical-line proposals t=1;
  • diagnostics, vertical-structure analysis, reports, and batch wrappers.
02 / DEVELOPMENT STAGE: PANOMIND OVERLAY + TOOLS

Visual control inside PTGui

Panomind Overlay brings diagnostics into Panorama Editor. The operator sees the multi-frame project structure in the same context where the stitched result is reviewed.

  • connection graph, CPs, verticals, quality buckets, and VPC;
  • quick launch of CP Assistant and VP Assistant automatic vertical detection;
  • a Windows product with settings, logs, and Core/GPU Runtime packaging.
03 / DEVELOPMENT STAGE: PANOMIND STUDIO + BATCH TOOLS

A lab and a repeatable pipeline

Studio provides dedicated space for precise CP selection: frame pairs, an ERP panorama, mask layers, and candidates before they are written to the project. A tuned solution is saved as a preset and becomes a dependable batch process for a capture series.

  • depth, segmentation, glass/mirror masks, and geometric filters;
  • saved presets instead of manually repeating settings;
  • the same presets run headlessly over a folder of projects.

PTGui assembles the panorama. Panomind explains where its geometry is unreliable and provides a controlled path from correcting one frame pair to improving a large project series.

Tools

Four roles in one controlled process

The system separates visual audit, interactive CP preparation, batch operations, and geometry utilities. A quick fix therefore does not become a heavy batch job, and a project series does not require manually repeating parameters.

Panomind Overlay

Audit in the current PTGui project

The Windows overlay reads the active .pts, builds a frame graph, and renders connections, CPs, verticals, a mask, and color-coded quality. On a multi-frame aerial panorama, it quickly reveals weak rings, missing links, VPC frames, and points requiring attention.

CP / VP Assistant

Targeted correction without leaving the editor

CP Assistant adds points on neighboring or missing links with geometric validation and spatial balancing. VP Assistant automatically finds vertical lines in scenes with walls and structures. Comparable automation for verticals is not part of a conventional stitcher feature set: it is a dedicated Panomind layer over the PTGui project.

Panomind Studio

A visual lab for CPs

The local web application opens a project in frame-pair and ERP modes. It shows existing CPs and candidates, lets the operator choose current models, segment objects, separate near and far planes with depth masks, and write only visually checked results with automatic backup.

Batch tools

Dependable processing for a series

cp_studio_batch.py applies a Studio preset to a folder of .pts projects; vismatch_cp_batch.py and vertical_cp_batch.py perform bulk enrichment. Other utilities prune verticals and center the sun from the image itself. Each project is included in a report, and writes are protected by backup.

Models and methods

New models work with geometry, not instead of it

Panomind combines current matching, segmentation, and depth models with geometric validation. This matters for complex aerial panoramas: a model may propose a stronger hypothesis, but only points that pass validation, masks, and visual review enter the project.

Key breakthrough, 2026

LoMa raises the bar for difficult correspondences

LoMa-B and LoMa-G are not simply more entries in a matcher selector. LoMa: Local Feature Matching Revisited builds quality through data, model-capacity, and training scale; its authors also created HardMatch, a set of genuinely difficult pairs where conventional tests no longer distinguish models well. This is especially relevant to aerial panoramas, where the challenge often comes from severe changes in viewpoint, scale, illumination, and texture rather than a lack of pixels.

In Panomind, LoMa works from full-resolution image paths rather than only a downscaled frame copy. Its role is to provide a strong hypothesis for the hardest links. Panomind then constrains the result with masks, RANSAC, a parallax filter, and visual review, so a high density of correspondences does not become a high density of errors.

PTGui and Panomind

Not a stitcher replacement, but a layer for analysis and controlled geometry

PTGui remains the primary tool for optimisation, stitching, rendering, and manual finishing. Panomind works beside it where multi-frame-link analysis, new models, and repeatable decisions for large series are required.

Task PTGui Panomind
Optimisation and final assembly Primary tool: optimiser, render masks, panorama stitching, and export. Does not duplicate the stitcher. It prepares and diagnoses project geometry, then returns it to the same .pts.

Use cases

Aerial panoramas in difficult conditions: from one link to a whole series

The level of automation can match the risk of the task: spot a problem quickly in Overlay, investigate a difficult pair in Studio, or move a tuned strategy to a large project series.

Fast aerial-panorama audit in PTGui

Open the project and Panorama Editor, enable Overlay, and inspect weak links, outliers, VPC, or missing verticals. In a multi-frame capture, this separates a local problem in one pair from a structural gap in the frame ring. When the diagnosis is clear, launch CP Assistant or VP Assistant from the same window.

Precise work on a difficult pair

In Studio, choose a pair or frame set and inspect existing CPs and candidates beside the ERP view. Use LoMa for a severe change in viewpoint or scale, and fast SIFT/ALIKED + LightGlue for ordinary links. Limit the search with a mask, apply RANSAC and the parallax filter. Only the validated candidate set is written to .pts.

Motion, water, reflections, and foreground

Enable semantic masks for sky, water, cars, people, vegetation, or other classes; DAM for reflective regions; and a depth mask for the near or far plane. CPs are then searched where the scene is geometrically reliable, not on accidental matches in moving or reflected objects.

A dependable panorama series

First tune the settings on a representative project, save a preset, run --dry-run, and then apply it to a folder of .pts files. The batch runner keeps a per-project report and backup; a consistent rig layout can be processed using selected frame indices. This turns one operator's expertise into a reproducible rule.

Original engineering

Original engineering turns new models into a controlled PTGui workflow

Panomind's value is not in renaming open models, but in the engineering system around them: it connects a model, geometry, visual explanation, writing to the project, and batch execution. That is what makes a new model usable on a real aerial-panorama series.

One geometry for display and writing

The projection model maps frame pixels to world rays and ERP positions. Overlay, Studio Panorama mode, and VPC calculation use the same projection context, so the visual explanation does not drift away from project geometry.

Semantics excludes unstable zones

Sky, water, cars, people, trees, and other classes become controllable masks. The operator can exclude them from CP search or inspect one class on its own. Inside/outside and detect/post modes make semantics a selection rule rather than a decorative AI layer.

Depth separates scene planes

A depth mask enables independent correspondence searches in the foreground and distant environment. This is particularly useful for an aerial panorama with nearby structures and a distant landscape: one mode does not have to explain two different geometries at once.

LoMa passes geometric scrutiny

LoMa provides strong full-resolution correspondences for difficult pairs, but then fundamental/homography RANSAC, spatial point balancing, and a parallax-outlier filter based on robust MAD statistics take over. More matches therefore do not mean more points written to the project.

Verticals are detected automatically

VP Assistant proposes t=1 lines in frames with walls and vertical structures. This is an uncommon level of automation for stitchers: Panomind does not merely accept ready-made lines, but generates candidates, shows them, and transfers them into the same project.

A preset connects Studio and batch

The preset format is identical for interactive Studio and the headless runner: masks, generation, write, VP, and parallax band. The operator tunes a rule once, then reproduces exactly that rule across a series, with a report and backup for every project.

Positioning

Panomind strengthens PTGui where complex geometry begins

PTGui optimises, stitches, and assembles the final panorama. Panomind adds observability and control to project preparation: it shows link structure, proposes candidates, finds verticals automatically, helps exclude unstable zones, and saves a solution as a repeatable operation.

The development sequence matters: working tools → Panomind Overlay + tools → Panomind Studio + tools for batch work. It makes new models part of a real production process rather than just a technology list.

One project from interactive work to batch

Panomind does not create an alternative project format. The tools read and update the source .pts; before writing, they create a backup and keep the result available for normal PTGui review.

  • Overlay provides fast visual diagnosis in the active project;
  • Studio shows candidates before they change the project;
  • one preset makes the tuned rule reusable in batch;
  • reports retain the outcome for each project in a series.
